# 04_DATA_ARCHITECTURE.md

## Data Architecture Overview

This document defines all data sources, storage formats, versioning strategies, and quality controls for the PREDIXA AI system. The architecture strictly separates historical data, real-time/live data, derived data, and model-generated data to prevent leakage and ensure reproducibility.

## Data Categories

### 1. Historical Data (Static, Append-Only)
Data that exists prior to system operation. Immutable once written.

| Dataset | Source | Frequency | Retention | Storage |
|---------|--------|-----------|-----------|---------|
| OHLCV (adjusted) | Yahoo/Polygon/Alpha Vantage | Daily | 10+ years | Parquet (partitioned by symbol/year) |
| OHLCV (unadjusted) | Same | Daily | 10+ years | Parquet |
| Corporate Actions | Same | Event-driven | 10+ years | PostgreSQL |
| Fundamental Data | SEC EDGAR, Financial APIs | Quarterly | 10+ years | Parquet (partitioned by symbol/quarter) |
| Market Indices | Same | Daily | 10+ years | Parquet |
| Sector/Industry ETFs | Same | Daily | 10+ years | Parquet |
| Historical News | News APIs, Archives | Daily | 5+ years | Parquet (partitioned by date) |
| Macro Data | FRED, Treasury | Daily/Monthly | 10+ years | Parquet |

### 2. Real-Time / Live Data (Streaming, Mutable Window)
Data arriving during market hours. Only the most recent window is mutable.

| Dataset | Source | Frequency | Latency | Storage |
|---------|--------|-----------|---------|---------|
| Live Quotes | Polygon, IEX, Alpaca | Second/Minute | < 1s | Redis (rolling window) |
| Intraday Bars | Same | 1min, 5min, 15min | < 5s | TimescaleDB (continuous aggregate) |
| Live News | NewsAPI, RSS, Webhooks | Event-driven | < 30s | PostgreSQL (recent 30 days) |
| Live Macro | FRED, Custom feeds | Daily/Event | < 1hr | PostgreSQL |

### 3. Derived Data (Computed, Versioned)
Features, labels, and datasets computed from raw data. Versioned with code + config hash.

| Dataset | Computed From | Versioning | Storage |
|---------|---------------|------------|---------|
| Price Features | OHLCV (adjusted) | Feature set hash + code hash | Feature Store (Feast/Parquet) |
| Technical Indicators | OHLCV | Feature set hash + code hash | Feature Store |
| Volatility Features | OHLCV | Feature set hash + code hash | Feature Store |
| Market-Relative Features | OHLCV + Indices | Feature set hash + code hash | Feature Store |
| Regime Features | OHLCV + Macro | Feature set hash + code hash | Feature Store |
| Fundamental Features | Fundamentals (lagged) | Feature set hash + code hash | Feature Store |
| News/Sentiment Features | News (lagged) | Feature set hash + code hash | Feature Store |
| Macro Features | Macro (lagged) | Feature set hash + code hash | Feature Store |
| Labels | OHLCV (forward returns) | Label config hash + code hash | Feature Store |
| Training Datasets | Features + Labels | Dataset hash (features + labels + split) | Parquet (ML-ready) |

### 4. Model-Generated Data (Output, Versioned)
Outputs from models. Immutable once created.

| Dataset | Generated By | Versioning | Storage |
|---------|--------------|------------|---------|
| Predictions | Prediction Engine | Model version + feature version + timestamp | PostgreSQL (predictions table) |
| Probabilities | Calibration Layer | Model version + calibrator version | PostgreSQL |
| Rankings | Ranking Engine | Model version + ranking config | PostgreSQL |
| Agent Decisions | Prediction Agent | Agent version + model versions | PostgreSQL |
| Backtest Results | Backtest Engine | Backtest config + model version | PostgreSQL/Parquet |
| Paper Trades | Paper Trading Engine | Timestamp + model version | PostgreSQL |
| Performance Metrics | Monitoring | Computation config + window | PostgreSQL |
| Drift Metrics | Drift Detector | Detector config + window | PostgreSQL

### Corporate Actions Handling

`mermaid
flowchart TD
    A[Raw Price Data] --> B{Split Detected?}
    B -->|Yes| C[Apply Split Factor to ALL historical prices]
    B -->|No| D{Dividend Detected?}
    D -->|Yes| E[Compute Total Return Price = Price + Dividend]
    D -->|No| F[No Adjustment]
    C --> G[Store Adjusted Series]
    E --> G
    F --> G
    G --> H[Validate: Adjusted Close == Raw Close * CumSplitFactor + CumDivAdjustment]
    H --> I[Flag Discrepancies > 0.01%]
`

Key Rules:
- Adjustments applied retroactively to all historical data
- Unadjusted prices preserved for audit
- Split factor: adjusted_price = raw_price / cumulative_split_factor
- Dividend adjustment: total_return_price = price + cumulative_dividends
- Validation: Recompute from actions; flag if drift > 1 basis point

### Timestamp Conventions
| Convention | Rule |
|------------|------|
| Storage | All timestamps UTC (ISO 8601: YYYY-MM-DDTHH:MM:SSZ) |
| Exchange Time | Original exchange timezone preserved as metadata |
| Trading Day | Defined by exchange calendar (NYSE/NASDAQ) |
| Daily Bar | timestamp = market close (16:00 ET = 20:00/21:00 UTC) |
| Prediction Time | Features computed as of prediction_timestamp (close of day T) |
| Label Time | Label computed from close of day T to close of day T+H |
| No Ambiguity | All timestamps timezone-aware; no naive datetimes |

### Data Frequency
- Primary: Daily (close-to-close returns)
- Secondary: Intraday (15-min bars for volatility features only)
- No High-Frequency: Tick data not used in v1 (complexity vs. edge tradeoff)

## Data Versioning Strategy

### Version Identifiers
`
# Feature Version
feat_v{major}.{minor}  # e.g., feat_v1.3
# Generated from: hash(feature_code + feature_config + dependency_versions)

# Label Version
label_v{major}.{minor}  # e.g., label_v2.1
# Generated from: hash(label_code + label_config)

# Dataset Version
ds_{feature_version}_{label_version}_{split_config_hash}
# e.g., ds_feat_v1.3_label_v2.1_split_expanding_30d_embargo_a1b2c3d4

# Model Version
model_{algorithm}_v{major}.{minor}.{patch}
# e.g., model_xgboost_v1.2.0
# Metadata: dataset_version, feature_version, label_version, hyperparams, metrics
`

### Versioning Rules
1. Any code/config change -> new version hash
2. Data correction -> new raw data version -> cascades to derived versions
3. Immutable: Once a version is used for training, it is frozen
4. Lineage: Every model artifact records exact dataset version used

## Missing Data Handling

| Scenario | Detection | Handling | Leakage Risk |
|----------|-----------|----------|--------------|
| Missing trading day (holiday) | Calendar check | Forward-fill from previous close (volume=0) | None - known in advance |
| Missing symbol (delisted) | Universe check | Flag survivorship; keep in historical with flag | High - MUST track delisting date |
| Missing price (halt) | Volume=0, price stale | Interpolate? NO - flag as missing, exclude from features | High - interpolation uses future |
| Missing fundamental | Report date check | Use last reported (with lag) | None if lag enforced |
| Missing news | Source check | Zero count, neutral sentiment | None - absence is information |

Critical: Never interpolate forward. Missing = missing. Model must handle NaN (tree models do natively).

## Duplicate Handling

| Duplicate Type | Detection | Resolution |
|----------------|-----------|------------|
| Same symbol, same date, same source | Primary key (symbol, date, source) | Keep first; log duplicate |
| Same symbol, same date, different sources | Cross-source validation | Prefer primary source; log discrepancy |
| Corporate action double-counted | Action ID uniqueness | Deduplicate by action_id; validate cumulative factor |

## Corporate Action Handling Detail

### Stock Splits
`python
# Pseudocode - applied at ingestion
split_factor = 1.0
for action in corporate_actions_sorted_by_date:
    if action.type == SPLIT:
        split_factor *= action.ratio  # e.g., 2:1 -> ratio=2.0
    adjusted_close = raw_close / split_factor
    adjusted_open = raw_open / split_factor
    adjusted_high = raw_high / split_factor
    adjusted_low = raw_low / split_factor
    adjusted_volume = raw_volume * split_factor
`

### Dividends
`python
# Total return adjustment
div_adjustment = 0.0
for action in corporate_actions_sorted_by_date:
    if action.type == DIVIDEND:
        div_adjustment += action.amount
    total_return_close = adjusted_close + div_adjustment
`

### Mergers & Acquisitions
- Delisting date recorded
- Final price recorded
- Post-merger: new symbol gets new history; old symbol frozen
- Survivorship flag: is_delisted=1, delisting_reason=MERGER

### Spinoffs
- Parent and child both continue
- Price adjustment for spinoff value
- Track as separate symbols from spinoff date

## Data Quality Checks

### Automated Checks (Per Ingestion Run)
| Check | Threshold | Action |
|-------|-----------|--------|
| Missing trading days | > 0 per symbol per month | Alert |
| Price outliers (z-score) | > 5 sigma | Flag, review |
| Volume outliers | > 10x median | Flag |
| High < Low | Any | Error - reject |
| Close > High or Close < Low | Any | Error - reject |
| Adjusted != Recomputed | > 1 bps | Alert |
| Split factor drift | > 1 bps | Alert |
| Fundamental lag | > 90 days | Alert |

## Summary: Data Category Boundaries

| Boundary | Enforcement |
|----------|-------------|
| Historical -> Derived | Batch pipeline, versioned, immutable |
| Live -> Derived | Incremental pipeline, same code as historical, feature store sync |
| Derived -> Model-Generated | Model version pins feature version; prediction logs immutable |
| No Backflow | Model outputs NEVER used as features (no recursive features) |
| No Future in Features | Feature computation timestamp <= prediction timestamp (enforced by code) |
| Lag Enforcement | Fundamental: 60-day lag; News: 1-day lag; Macro: 1-day lag |
